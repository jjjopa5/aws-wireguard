# Работа с aws-wireguard

Эти инструкции относятся ко всему репозиторию. Перед работой прочитай AGENTS.md и CLAUDE.md.
При изменении договорённостей, устройства туннеля или отложенных задач обновляй оба файла в одной правке.
Проверка синхронности из корня — `diff -u AGENTS.md CLAUDE.md`.

## Окружение

- Рабочий EU-туннель находится в аккаунте `347288885877`, профиль `k8s-lab-admin`, регион `eu-central-1`.
  Перед операциями с AWS сверь ID через `aws sts get-caller-identity --profile k8s-lab-admin --query Account`.
- Terraform запускай из `infra/` или с `-chdir=infra`. Ключ S3 state — `wireguard/terraform.tfstate`.
  Нужен Terraform >= 1.11. На Mac проверку проходил `~/bin/terraform` версии 1.15.9.
- Terraform управляет AWS-ресурсами, пакетами и форвардингом при создании EC2. Ключи и конфигурация пиров
  находятся в `/etc/wireguard`. При замене машины восстанови каталог и проверь второй SSH-ключ,
  добавленный вручную в `authorized_keys`. Подробности — в README.md. Конфиги с ключами храни вне Git.

## Маршруты и клиенты

- Сохраняй `vpn-routes.txt` в корне ветки `main`. Его raw-ссылку использует `~/update-vpn-routes.sh`
  на Mac. Скрипт содержит клиентский приватный ключ. При ручной смене Endpoint учти кеш маршрутов.
  На iPhone и iPad владельца настройки обновляются вручную.
- Split-туннель обслуживает IPv4 и IPv6. Если сервис использует AAAA, проверь, что нужный IPv6-префикс
  входит в AllowedIPs. Для выхода из `fd00:8::/64` в заметке Claude описан MASQUERADE на `ens5`
  в PostUp/PostDown. При восстановлении сверь внешний интерфейс с таблицей маршрутизации сервера.
- Список включает адрес API Kubernetes-лабы. По заметке от 02.11.2026 её firewall разрешал
  вход с публичного IPv4 VPN. При смене endpoint сверь allowlist лабы. Общие диапазоны Google
  договорились не добавлять.
