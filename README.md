# aws-wireguard

Личный split-tunnel WireGuard на AWS, eu-central-1. Dual-stack: внутри туннеля
IPv4 `10.8.0.0/24` и ULA `fd00:8::/64`, наружу — через egress-only IGW.

## Где что лежит

- `infra/` — **актуальный код**, аккаунт `347288885877`, профиль `k8s-lab-admin`,
  remote state в S3 (`k8s-lab-tfstate-347288885877`, ключ `wireguard/terraform.tfstate`).
- корень репо (`ec2.tf`, `vpc.tf`, ...) — **старый аккаунт `229535221334`**, локальный
  state. Держится только ради финального `terraform destroy`, когда переезд устаканится.
  Новые правки туда не вносить.
- `vpn-routes.txt` — список маршрутов для split-режима. **Лежит в корне и переезжать
  не должен**: на него смотрит raw-ссылка из `~/update-vpn-routes.sh` на маке.

## Переезд 27.08.2026

Старый аккаунт был на бесплатном плане, кредиты и срок заканчивались. Инфраструктура
поднята заново в новом аккаунте один в один: та же адресация VPC, тот же t3.micro,
тот же egress-only IGW.

Что изменилось для клиентов — **только `Endpoint`**:

| | было | стало |
|---|---|---|
| Endpoint | `18.156.108.6:51820` | `63.188.144.22:51820` |

Ключевая пара сервера перенесена как есть, поэтому `PublicKey` сервера у пиров
прежний, и правится ровно одна строка. Адреса `10.8.0.x` / `fd00:8::x`, ключи пиров
и список маршрутов не менялись.

Глобальный IPv6-префикс новый (`2a05:d014:12ad:300::/56` вместо
`2a05:d014:1c16:5b00::/56`) — он используется только для исходящих, клиентов не касается.

## Чем новый код отличается от старого

- AMI через `data "aws_ami"` вместо захардкоженного id
- правила SG отдельными ресурсами вместо inline-блоков
- `user_data` ставит `wireguard`/`qrencode` и включает форвардинг — раньше это делалось
  руками. Ключи и `wg0.conf` в user_data не попадают, они переносятся отдельно.
- remote state в S3 с нативным локингом (`use_lockfile`) вместо локального файла

## Перенос состояния сервера

Терраформ поднимает пустую машину. Всё, что делает её VPN-сервером, живёт в
`/etc/wireguard` и переносится потоком, не оставляя ключи на диске без нужды:

```bash
ssh -i ~/.ssh/id_ed25519 ubuntu@СТАРЫЙ 'sudo tar czf - -C /etc wireguard' \
  | ssh -i ~/.ssh/personal ubuntu@НОВЫЙ 'sudo tar xzf - -C /etc'
ssh -i ~/.ssh/personal ubuntu@НОВЫЙ 'sudo systemctl enable --now wg-quick@wg0'
```

Проверить, что интерфейс наружу называется `ens5` — он захардкожен в `PostUp`/`PostDown`
внутри `wg0.conf`. На Graviton-инстансах имя будет другим.

## Клиенты

- **Mac** — конфиг перегенерирует `~/update-vpn-routes.sh` (Endpoint и ключ сервера
  зашиты в нём). Скрипт выходит молча, если `vpn-routes.txt` не менялся, поэтому после
  правки Endpoint нужно сначала снести кеш: `rm /tmp/vpn-routes.cache`.
- **iPhone / iPad владельца** — приватных ключей на сервере нет, Endpoint правится
  руками в приложении.
- **Остальные пиры** (Shpakovskiy Maxim ×2, Danik, Anton) — тоже правка одного поля.
  Приватные ключи Danik, Anton и телефона Максима лежат на сервере в `/etc/wireguard`,
  так что при необходимости их конфиги можно пересобрать и отдать QR через `qrencode`.

## Доступ на сервер

`aws_key_pair` в терраформе кладёт один ключ — владельца. Второй ключ (Максим, он же
хозяин бота, который переезжает отдельно) добавлен вручную в
`/home/ubuntu/.ssh/authorized_keys` и в терраформе не описан: репозиторий публичный,
чужие ключи и почты в него класть незачем.

Из этого следует: **при пересоздании инстанса второй ключ пропадёт** — забрать его
со старой машины или попросить прислать заново.

И помнить, что `ubuntu` ходит под passwordless sudo, то есть любой, у кого есть ssh
на эту машину, читает `/etc/wireguard` целиком — включая приватные ключи всех пиров.
